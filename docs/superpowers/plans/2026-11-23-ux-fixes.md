# UI/UX fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the findings of the 2026-11-23 UI/UX review, most harmful first, without changing game behaviour.

**Architecture:** Small, local UI changes in each game's `client/`, the room shell (`apps/web/src/views/`), shared UI (`packages/ui`), and CouchParty's own apps on the `product` branch. No server rule changes.

**Tech Stack:** TypeScript, plain DOM via `h()` from `@games/ui`, CSS, Vitest, Cloudflare Workers (wrangler dev for local checks).

**Spec:** `docs/superpowers/specs/2026-11-23-ux-fixes-design.md`. Findings with file pointers: `docs/superpowers/reviews/2026-11-23-ui-ux-review.md`.

## Global Constraints

- "functionally nothing should change only the UI": move, restyle, relabel or reveal controls. Do not change rules, scoring, or what the server accepts.
- Player copy: short plain sentences, basic words, no idioms or US/UK slang, for Indian readers with English as a second language. No emoji anywhere (UI, docs, commit messages). Icons are inline SVG.
- Phone portrait 360x780 is the main check; landscape 780x360 where the game is played sideways; desktop 1280x800 must stay sane. Tap targets at least 40 px where there is room.
- Keep `docs/games/*.md` in step with any player-visible wording you change.
- If a wire message or room state changes shape, bump `PROTOCOL_VERSION` in `packages/protocol`.
- Every task ends green: `pnpm typecheck` and `pnpm vitest run` (or the affected folders while iterating, the full run before committing).

## Review Focus

- A late tap in Face-Off after someone buzzed must not land on Redo or a vote button at any card text length.
- A President game in progress, saved with the old title strings, must still render and finish after deploy.
- Lobby bottom bar must not cover the last lobby control (Leave room / End party) on a 360x780 phone, and must not show on desktop if it hurts layout.
- The in-app confirm must work for keyboard (Escape = cancel, Enter on the focused button) and must not leave a stale dialog when the room re-renders.
- Room re-renders arrive often (every state update): any new open/closed UI state (folds, bars, dialogs) must survive a re-render instead of snapping back.
