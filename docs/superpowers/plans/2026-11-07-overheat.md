# Overheat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Overheat, a 2–8 player push-your-luck card game, as `games/overheat` on the existing room runtime, playable in the lobby under **Cards**.

**Architecture:** Same shape as `games/farkle`. `shared/` holds types, pure card and scoring rules, the manifest and the lobby rules text. `server/game.ts` is a `GameDefinition` that clones state, mutates the clone through small helpers, and returns events and timers. `client/view.ts` is a `GameView` that draws one row per player and animates from events. The deck order is server-only. Everything else is public.

**Tech Stack:** TypeScript 6, vitest 5, pnpm workspaces, `@games/game-core`, `@games/ui`, `@games/animation`, `@games/audio`. Dev is `pnpm dev` (vite + wrangler on :8787, owner key `dev`).

**Spec:** `overheat-spec.md` (repo root). Read it alongside this plan. Section numbers below (§3.2 etc.) refer to it.

## Global Constraints

- Package `@games/overheat`, directory `games/overheat`, manifest `id: "overheat"`, `minPlayers: 2`, `maxPlayers: 8`, web registry `section: "cards"`.
- Randomness only through `ctx.randomInt`. Use `shuffle` from `@games/game-core` for the deck. Gauge = `GAUGE_MIN + ctx.randomInt(GAUGE_MAX - GAUGE_MIN + 1)`, with 18 and 30.
- Deck order never appears in public state, private state, or any event. Public state carries `deckCount` and `discardCount` only.
- Heat never goes below 0, after any change (Vent, Wrench).
- Bust is strictly `heat > gauge`. Redline is exactly `heat === gauge`. Both are checked after every change, for every player the change touched.
- Site copy (rules text, status lines, buttons, docs page) is plain Indian English: short sentences, basic words, no idioms. Never use "busted out", "on fire" style idioms.
- Colour is never the only signal. Each colour has a fixed shape: red = circle, amber = triangle, blue = square, green = diamond.
- Phone-first: the table must work at 360 px width with touch, like Farkle.
- Commits go straight to `master`, one per task, and are pushed after each commit. Subject line `Overheat: <what a player gets>`, then a short body that explains why, in the style of `git show a176078`. End every message with `Claude-Session: https://claude.ai/code/session_01KwNUn9dpkZKSPFkAmAoz5c`.
- Run tests with `pnpm vitest run games/overheat` and typecheck with `pnpm --filter @games/overheat typecheck`. Both must be clean before a commit.

## Review Focus

1. **Deck and discard both empty** (8 players, long rounds with Vents). A Flip with nothing to draw banks the flipper, and a Shove with nothing to draw fizzles. No throw. Test is in Task 3.
2. **Shove chains.** A Shove flips an aimed card into the target, so the *target* chooses. Awaited player = the chooser, not the turn owner. Once that choice resolves, the turn passes on from the turn owner's seat. Test is in Task 3.
3. **A player leaves mid-choice or on their own turn.** The pending card is dropped with no effect and play goes on. Down to 1 player, the game ends as `abandoned`. Test is in Task 4.
4. **Fuse tick ends a turn before it starts.** The tick busts or redlines the player, then the turn moves to the next player still flipping. If nobody is left, the round ends. Test is in Task 3.
5. **Stale or hostile actions.** Wrench card ids not in those engines, targeting yourself or a banked player, any action during the round-end pause, Bank on a first turn. Each is rejected and state stays unchanged. Tests are in Tasks 2 and 3.

  Card ids for codes in `stateWith` are assigned sequentially in this order: players' engines first, then the deck, then the discard. Tests look cards up by id in state, so the exact numbering doesn't matter.

Rules this task pins (spec §3):
- `createGame`: throws outside 2–8 players. `deck = shuffle(buildDeck(settings.powers), ctx.randomInt)`, except when `options.deck` is given: then the deck is exactly those codes in order, top first, and `createGame` throws on a bad code. `firstIndex = dealerSeat mod n`. Then start round 1.
- Round start (`startRound`): move every engine card into `discard`, roll the gauge, and reset each non-removed player to `status "flipping", engine [], heat 0, gauge = round gauge, fuses 0, turbo false, flipped false, redline false, roundPoints 0`. Emit `round-start`, then begin the turn at `firstIndex`.
- Draw (`draw`): when `deck` is empty, shuffle `discard` into `deck` and emit `reshuffle`. Returns null if both are empty.
- Flip: one card per turn. A number card joins the engine, `heat += value*mult`, emit `flip` (with heat after), then check.
- Check (`check(state, idx, out)`): `heat > gauge` → `status "busted"`, `roundPoints 0`, emit `bust`. `heat === gauge` → `redline = true`, emit `redline`, then bank.
- Bank: `roundPoints = bankScore(engine, redline)`, `score += roundPoints`, `status "banked"`, emit `bank`. Banking on a turn where `flipped` is false is rejected with `must-flip`.
- Advance: after a flip or bank resolves, find the next player in seat order (wrapping, starting after `turnIndex`) whose status is `flipping`. This can be the same player. If there is none, the round ends.
- Round end: emit `round-end`. If any score ≥ target, finish: winners are all non-removed players on the top score, emit `game-over`, no timer. Otherwise `step "round-end"`, `roundEndsAt = ctx.now + ROUND_END_MS`, and set timer `"next-round"`. `onTimer("next-round")` moves `firstIndex` to the next non-removed seat, `round++`, and starts the round.
- Rejections, in this order: `game-finished`, `not-in-game`, `round-over` (step is round-end), `not-your-turn`, `must-flip`. `parseAction` returns null for unknown shapes.
- Awaited: `step "turn"` gives `[current]`, anything else gives `[]`. Result standings are sorted by score with label `"142 pts"`; removed players get label `"left"` and sort last.

### Task 3: Power cards

**Files:**
- Modify: `games/overheat/server/game.ts`
- Test: `games/overheat/test/powers.test.ts`

**Interfaces:**
- Consumes: Task 2's internals (`draw`, `check`, bank, advance) and `test/helpers.ts`.
- Produces: `resolvePower(state, idx, card, ctx, out)`, the one entry point for "player `idx` resolves this power card as its flipper". Flip and Shove both route through it. Also `validTargets(state, chooserIdx, kind): number[]`, which Task 4's Skip reuses. After resolving, every power card goes to `discard`, except a Fuse, which goes to discard at the next round start (keep a count only; the card itself can go straight to discard).

Rules this task pins (spec §3.2–§4):
- **Vent:** `heat = max(0, heat − 5)`. Points don't change. Emit `vent`, then check (a vent can't bust, but keep one code path).
- **Turbo:** sets `turbo = true` (a second Turbo does nothing extra) and emits `turbo`. The next number card that goes into this engine by a flip (including a shoved flip) gets `mult: 2` and clears `turbo`. Cards swapped in by Wrench never use Turbo.
- **Heatwave:** every player still flipping, the resolver included, gets `gauge -= 3`. Emit `heatwave` with `hit` in seat order starting from the resolver, then check each in that order.
- **Aimed (Shove, Wrench, Fuse):** valid targets are other players who are `flipping`. For Wrench, the target also needs ≥1 engine card, and the chooser needs ≥1 engine card or there are no valid targets. With no valid targets: emit `fizzle` and discard the card. Otherwise `step "choosing"`, `pending = { kind, chooserId, card }`, awaited `[chooserId]`.
- **Choice actions:** only `pending.chooserId` may send them (`not-choosing` for anyone else, or for the wrong action type). `target` resolves Shove/Fuse. `wrench` must name a target in `validTargets`, `mine` in the chooser's engine and `theirs` in the target's engine (`bad-target` / `bad-card`).
  - **Fuse:** target `fuses++`, emit `fuse`.
  - **Wrench:** swap the two `EngineCard`s with their mult. Each player's heat changes by the value×mult difference, floored at 0. Emit `wrench`, then check the chooser, then the target.
  - **Shove:** emit `shove`, then draw. Nothing to draw → `fizzle` with `card: null`. A number card goes into the target's engine (flip event with `by`) and the target is checked. A power card → `resolvePower` with the target as its flipper, which can open a new pending choice for the target.
- Once no pending choice remains, advance from `turnIndex` (the turn owner's seat), not from the chooser's.
- **Flip with nothing to draw:** the flipper banks (emit `fizzle` with `card: null`, then `bank`).
- **Fuse tick:** at the start of a player's turn (in advance, before they act) with `fuses > 0`: `heat += fuses`, emit `fuse-tick`, check. If they are no longer flipping, keep advancing. If nobody is left, the round ends.

### Task 4: Skip, leaving, and the balance simulation

**Files:**
- Modify: `games/overheat/server/game.ts`
- Test: `games/overheat/test/flow.test.ts`, `games/overheat/test/sim.ts`, `games/overheat/test/balance.test.ts`

**Interfaces:**
- Consumes: `validTargets` from Task 3, helpers from Task 2.
- Produces: `skipTurn` and `onPlayerRemoved` on `overheatGame`. Also `simulate(opts: { players: number; rounds: number; seed: number }): { bustRate: number; avgEngineCards: number; avgFlipsPerRound: number }` in `test/sim.ts`.

Rules:
- **skipTurn(playerId):** no-op unless `playerId` is awaited. With a pending choice: pick a random valid target with `ctx.randomInt`, and for Wrench, random `mine` and `theirs` too. Otherwise: bank if `flipped`, else flip. Emit `turn-skipped` first.
- **onPlayerRemoved:** set `removed`, `status "out"`, emit `player-removed`. Under 2 non-removed players → finish with `abandoned`. If they were the pending chooser, drop the pending card (to discard, no effect) and advance from `turnIndex`. If it was their turn, advance. A removed player can never be a target and is skipped by every rotation.
- **Sim bots:** on their turn, bank when `flipped && heat >= gauge - 6`, else flip. Choices use the same random pick as Skip. A round counts each non-removed player's outcome. Bust rate = busts / player-rounds. Run whole games back to back until `rounds` rounds have finished, with powers `classic`.

What the view must do (spec §7 Client). Use `games/farkle/client/view.ts` as the pattern for `update`/`render`/`AnimationQueue`/sounds/`setTurn`/`rejected`.
- Header: round number, the round gauge, deck count, and a status line (`role="status"`) that says whose turn it is and what to do: "Your turn. Flip a card or bank.", "Pick a player to shove a card onto.", "Pick one of your cards, then one of theirs."
- One row per player: avatar and name, banked score, status chip (Flipping / Banked +N / Bust / Left), a fuse icon ×N, and engine cards. A card shows its number, its colour and its colour's shape, and a "×2" mark when the mult is 2.
- **Heat bar:** fill = heat / gauge, with a gauge line marker and the text `heat / gauge`. Colour goes from cool to hot as heat nears the gauge, via a CSS custom property. Add a shake class when `gauge − heat <= 3` and the player is still flipping. Respect `prefers-reduced-motion`.
- Dock for the acting player: **Flip** and **Bank +N** (N = `bankScore` preview). Bank is disabled with the hint "You must flip first" on a first turn. While choosing, valid target rows are tappable buttons. Wrench is two taps: one of my cards, then one of theirs, then send `{type:"wrench", targetId, mine, theirs}`.
- Events animate in order: the flipped card lands in its row, Shove shows a short arrow or label from the shover to the target, a bust shakes and dims the row, a redline flashes, Heatwave flashes every hit row's gauge line, and a fuse tick pulses the fuse icon. Each event also writes a plain sentence to a log line, like Farkle's `describe` ("Asha shoved a Red 8 onto you. Bust!").
- Round-end: show each player's round result until `roundEndsAt`. Finished: the shell's results screen takes over.
- 360 px width: rows stack, cards wrap, buttons are at least 44 px tall.
